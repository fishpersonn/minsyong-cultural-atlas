# 資料維護

這份文件寫給維護資料的人：資料從哪來、怎麼更新、格式與規則。網站本身的介紹見[根目錄 README](../README.md)。

## 資料從哪來

資料來自爬蟲專案 `dovoha-Web-Crawle`（爬取大學路官網文章、整理成帶座標的 GeoJSON）。本站分兩條路進來：

| 主題 | 來源 | 怎麼進來 |
| --- | --- | --- |
| 民雄鐵路高架化 | 爬蟲專案 `2026-團隊研究調查-民雄鐵路高架化/` | 直接複製 JSON 到 `src/data/railway.json` |
| 其他 14 個主題 | 爬蟲專案 `2025-民雄文化地圖整理/` | 用腳本轉換，輸出到 `src/data/crawler/` |

## 更新鐵路高架化

把爬蟲輸出的 JSON 複製過來覆蓋：

```bash
cp <dovoha-Web-Crawle>/2026-團隊研究調查-民雄鐵路高架化/MinxiongRailwayElevation_Output/民雄鐵路高架化.json \
   src/data/railway.json
```

`<dovoha-Web-Crawle>` 是爬蟲專案在你電腦上的路徑。覆蓋後執行 `npm test`、`npm run build`，沒問題再 commit。
新文章要同時補上 `src/data/railway.meta.json` 的對應項目（見下方「分類、年代與發布日期」），測試會檢查兩邊 ID 一一對應。

## 更新其他主題

```bash
node scripts/import-crawler.mjs <dovoha-Web-Crawle 路徑>
```

- 各主題的欄位名稱不一致（地點、name、名稱…），腳本最上面的 `THEMES` 集中記錄每個主題用哪個檔案、哪些欄位對應標題／摘要／連結／分類／年代。
- 輸出的每個地點欄位統一為：`name`、`摘要`、`查看更多`、`圖片`、`id`、`分類`、`年代`、`extra`。
- 沒有匯入爬蟲專案裡的 `backup/` 舊版本、重複檔案，以及徵文比賽（只有 csv、沒有座標）。

### 新增一個主題

1. 在 `scripts/import-crawler.mjs` 的 `THEMES` 加一筆，執行腳本產生 `src/data/crawler/<id>.json`。
2. 在 `src/data/themes.ts` 匯入並登錄（順序就是篩選列的顯示順序）。
3. 在 `src/lib/themeStyles.ts` 加這個主題的標記顏色與圖示。

測試會檢查：每個主題都能解析、沒有被略過的資料、全站地點 id 不重複、每個主題都有標記樣式。

## 地點 id 與專屬網址

網址 `#p=<id>` 用的就是地點 id。**id 一旦分享出去就不能隨便改**：

- 鐵路高架化：純數字，取自官網連結（例如 `…/405-1159-96220,c4204.php` 的 `96220`）。有第二個連結的合併文章，以第一個連結為準。
- 其他主題：`<主題>-<官網文章編號>`，例如 `podcast-61177`。同一篇文章對應多個地點時加 `-2`、`-3`；沒有官網連結的地點用 `<主題>-i<第幾筆>`。
- **資料順序變動，會讓沒有官網連結的地點 id 改變**，已分享的網址可能失效。更新資料時請盡量只在檔尾新增，不要重排。

ID 找不到對應地點時，視為沒有選取，不會顯示錯誤頁。

## 分類、年代與發布日期（補充資料）

爬蟲輸出沒有分類與年代。鐵路高架化的這些資訊放在獨立的 `src/data/railway.meta.json`（以文章 ID 為鍵），重新複製爬蟲 JSON 不會蓋掉它：

```json
"96220": { "category": "歷史故事", "era": "1963", "published": "2026-10-15" }
```

- `category`：分類。顯示用的顏色與圖示定義在 `src/lib/categories.ts`；新增分類要同步加進去，否則會用灰色。
- `era`：年代，**只收標題或摘要裡明講的時間**（如 `1963`、`日治時期`），沒有就不要填。
- `published`：官網文章的發布日期（`YYYY-MM-DD`），取自各文章頁面的「發布日期」。
- 資料檔本身若也有 `分類`、`年代` 欄位，以資料檔為準。

其他主題的分類與年代則由匯入腳本直接寫進資料（例如民雄人物的「主分類」、美食的「國家」）。

## 資料格式與驗證規則

資料是 GeoJSON `FeatureCollection`（`features` 陣列）。每個 feature 的欄位對應如下（`src/lib/parsePlaces.ts`）：

| 原始欄位 | 對應到 `Place` | 說明 |
| --- | --- | --- |
| `geometry.coordinates` `[經度, 緯度]` | `lng`、`lat` | 必填 |
| `properties.name` | `title` | 必填，不可為空白 |
| `properties.id` | `id` | 選填。有就直接使用（匯入腳本產生）；沒有則從 `查看更多` 擷取 |
| `properties.查看更多` | `links[0]` | 沒有 `id` 時必填，網址需含 `-<數字>,c<數字>`（或 `-<數字>.php`）才能取得文章 ID |
| `properties.查看更多2` | `links[1]` | 選填，合併文章用 |
| `properties.摘要` | `summary` | 選填，缺少時為空字串 |
| `properties.圖片`、`圖片2` | `images` | 選填 |
| `properties.分類`、`年代` | `category`、`era` | 選填 |
| `properties.extra` | `extra` | 選填，`[標籤, 內容]` 的陣列，卡片上顯示成「標籤　內容」（如美食的地址、電話） |

下列資料會被跳過（不顯示在地圖上，不會讓網站壞掉；開發時 console 會列出原因）：

- 缺少座標，或座標不是有效數字
- 座標超出範圍：經度需在 118–123、緯度需在 21–26（見 `src/constants.ts`）
- 缺少標題（`name`）
- 沒有 `id`，也沒有 `查看更多` 連結，或連結中找不到文章 ID
- 地點 id 與同一主題前面的地點重複

沒有任何連結的地點，卡片按鈕會顯示「前往大學路官網」並連到首頁，不假裝有文章。

## 地圖上的呈現規則

- 座標完全相同的地點會合併成同一個標記，卡片裡可以切換。
- 螢幕上相距不到 40 像素的標記會再合併成數字標記；縮放到街道等級（zoom 17）後不再合併。
- 初始視野會排除離中位數超過 10 公里的離群點。
- 標記顏色與圖示：有設定樣式的分類（鐵路高架化的 5 個分類）優先，其次是主題樣式，最後是灰色。
