# 民雄文化地圖網頁（第一版：鐵路高架化）設計文件

日期：2026-10-25｜狀態：草稿，待確認

## 1. 目的與為什麼

民雄文化地圖的資料來自中正大學「重構大學路計畫」官網（dovoha.ccu.edu.tw，以下稱「大學路官網」）。我們沒有官網後台權限，無法改官網，但可以做一張網頁地圖當**入口與媒介**。

- **使用者**：不熟悉民雄、想認識民雄文化的外地人，手機和電腦都會用。
- **主要產品**：一張好用、好看的互動式地圖，讓人探索鐵路高架化沿線的地點與故事。
- **與官網的關係**：地圖是紀錄與媒介。每個地點都附連結，帶有興趣的人回大學路官網讀完整文章、看影片或聽 Podcast。引流是效果之一，不是唯一目的。
- **成功的標準**：外地人打開後能順暢探索地點、看懂每個地點的故事；想深入的人能一步到達官網。不量測點擊數。

## 2. 目標、非目標、反目標

**目標**
- 一張可在手機與電腦瀏覽的互動地圖，呈現「民雄鐵路高架化」主題的 24 個地點。
- 點地點出現卡片（標題、圖片、摘要、前往官網按鈕）。
- 每個地點有可分享的專屬網址。
- 之後能擴充新增主題（78 點合併地圖與十幾個主題資料夾），不必重做。
- 部署在 GitHub Pages，推上 main 即自動更新。

**非目標（第一版不做）**
- 其他主題的資料、英文或多語系、使用者登入、留言、後台編輯介面、搜尋與篩選、路線（線形）呈現。
- 在地圖內放文章全文。
- 任何點擊或流量統計（使用者已決定不需要）。

**反目標（即使技術上成功也算失敗）**
- 卡片放入全文，使官網連結失去意義（卡片只放預覽）。
- 一筆壞資料（缺座標、圖片失效）讓整張地圖或頁面壞掉。
- 手機上難以操作。

## 3. 使用者決定的事（原話為準）

- 對象是想了解民雄文化的外地人；地圖是紀錄與媒介；網站主體是互動地圖，導流到大學路官網是效果之一。
- 互動形式採 **A＋B**：獨立網站，點位彈出卡片附官網連結，每個地點有專屬網址。
- 第一版只做鐵路高架化的 24 個點。
- 技術：**Vite + React + MapLibre GL**，GitHub Actions 自動部署到 GitHub Pages。
- 手機與電腦都要支援；語言先繁體中文。
- 要可擴充；維護者只有使用者一人。
- 開發模式：人當 Navigator 決定方向與驗收，AI 當 Driver 實作；搭配防禦式設計。
- 使用者尚未對介面有具體想像，介面細節交給建置者提案，由使用者看成品調整。

## 4. 限制

- 無法修改大學路官網，也不能假設官網允許被嵌入。
- 純靜態網站，沒有後端與資料庫。
- 官網圖片與連結是別人的伺服器，可能改版、失效。
- 資料由爬蟲與手動標記產生，品質不一（見第 6 節）。

## 5. 設計

### 5.1 介面行為
- 全螢幕地圖，初始範圍框住民雄車站周邊的點。
- 地點以標記呈現；點選後顯示卡片：標題、圖片、摘要、醒目的「到大學路官網閱讀」按鈕（新分頁開啟，地圖頁保持）。
- 頁面上有固定的「前往大學路官網」入口，沒點任何地點的人也有路可走。
- 手機以版面優先設計（卡片可為底部抽屜），電腦可為側欄或浮動卡片，形式由建置者提案。
- 底圖用 OpenFreeMap（Liberty／Bright／Positron 擇一，淡色為佳，讓標記突出）。**這是 AI 的建議**，開工時須實測可用；備案為 CARTO Positron／Voyager。

### 5.2 專屬網址
- 格式 `…/#p=<文章ID>`，文章 ID 取自官網連結中的數字（例：`…96220,c4204.php` 取 `96220`）。
- 打開專屬網址時，地圖定位到該點並開啟卡片；點選或關閉卡片時網址同步更新，上一頁與重新整理可還原狀態。
- 指向不存在的 ID 時，回到全圖，不顯示錯誤頁。
- **這是 AI 的建議**：用 ID 而非順序，理由是資料增減或重排不會讓分享出去的連結失效。若不用 hash，可改其他方式，但須在 GitHub Pages 上可行。

### 5.3 資料
- 主題資料各自一個 JSON 檔，欄位統一；新增主題即新增一個檔案並登錄。
- 第一版來源：`dovoha-Web-Crawle/2026-團隊研究調查-民雄鐵路高架化/MinxiongRailwayElevation_Output/民雄鐵路高架化.json`（GeoJSON，24 點）。複製進本專案，更新時手動重新複製。
- 原欄位：`name`、`摘要`、`查看更多`、`圖片`；部分合併過的文章另有 `查看更多2`、`圖片2`（卡片如何呈現多個連結由建置者決定）。
- 統一後的內部欄位至少含：id、標題、摘要、官網連結、圖片、座標、主題。

### 5.4 防禦式設計
- 載入資料時逐筆驗證：缺座標、座標超出合理範圍、缺標題或缺官網連結的點，跳過並在開發時給出提示，不影響其他點。
- 圖片載入失敗時顯示預設圖。
- 官網連結缺失時，按鈕退回大學路官網首頁，不顯示壞連結。
- 資料驗證邏輯有自動測試。
- 結構上資料、地圖、卡片分成獨立模組；不引入微服務或 micro-frontend。
- 型別使用 TypeScript（**AI 的建議**，理由是欄位多、之後擴充主題時型別能抓錯）。

### 5.5 開發與部署流程
- 人當 Navigator，AI 當 Driver：AI 實作，每個階段停下讓使用者看並驗收，不一口氣做完。
- GitHub Issues／Projects 看板，一功能一張卡；功能分支＋Pull Request；Conventional Commits。
- GitHub Actions：型別檢查、測試、建置，通過後部署至 GitHub Pages。
- 建議階段順序：資料整理與驗證 → 地圖與標記 → 卡片 → 專屬網址 → 手機版面 → 上線。

## 6. 資料現況的注意事項（來自實際檢查）

- 24 筆中有多筆**座標完全相同**（例如農會倉庫相關 3 筆都在 120.43204, 23.55834；民雄車站附近也有 3 筆重疊）。地圖上會疊成一個點，必須設計如何呈現（例如群集展開，或同點卡片列表）。
- 兩筆明顯在民雄車站範圍之外：「鐵路高架化之後：橋下空間的國內外案例觀摩」（約台中，120.68, 24.14）與「【烈風講堂】變身中的百年打貓驛與在地記憶」（約 23.524, 120.439，講堂舉辦地）。初始視野不應被台中那一筆拉得過大。
- 摘要長度約 64 到 283 字，其中部分以「…」截斷，可直接作預覽。
- 工作紀錄中的待辦：講堂座標是否保留、範圍／路線類（如民雄文化廊帶地圖）是否改為線形——第一版維持單點，線形列為後續。

- 資料來源檔在本機 `dovoha-Web-Crawle` repo，複製進本專案使用。

**AI 的決定（使用者可推翻）**
- 官網首頁連結與備援連結用 `https://dovoha.ccu.edu.tw/`。
- 圖片直接引用官網網址（hotlink），不複製到本專案，避免版權與同步問題；預設圖由建置者製作。若實測被官網擋下，再回來討論。
- 瀏覽器目標為常見瀏覽器的近期版本（含 iOS Safari）。沒有 WebGL 或地圖初始化失敗時，捕捉錯誤並顯示一句提示（如「你的瀏覽器不支援互動地圖」）加上前往大學路官網的連結，不顯示空白頁。地點清單視圖列為後續功能。
- 台中那一筆保留在資料中，但初始視野只框住民雄周邊。
- 驗收方式：本機執行預覽，合併後看正式的 GitHub Pages；不設定每個 PR 的預覽部署。
